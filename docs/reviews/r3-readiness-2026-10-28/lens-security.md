## Findings (ordered by severity)

Legend: CONFIRMED = reproduced by PoC/test or unambiguous from code; PLAUSIBLE = depends on environment/deployment not exercised here.

### M1. Worker disk-fill: RW workspace bind mount has no quota, no `fsize` ulimit - Medium - CONFIRMED (code), not executed (docker prohibited)
- src/panestria/sandbox/runner.py:165-197 (create args), src/panestria/sandbox/profiles.py (no disk field).
- `/tmp` is a size-capped tmpfs, but `/workspace` is `type=bind,src=<host dir>` and writable for `scoped-code-edit`. Only `nofile` and `core` ulimits are set; `--storage-opt` does not apply to bind mounts. A model-authored `bash -c 'dd if=/dev/zero of=big bs=1M'` inside the 30 s wall can write multiple GB to the host filesystem (host-uid owned). Later caps (candidate 32 MiB, 4000 entries) are enforced only at capture, after the disk is already full; the failure then affects the Postgres host and every other service.
- Related: `ArtifactIngress._read_source` (artifact_ingress.py:161) does an unbounded `read_bytes()` of a worker-written file (synthetic R0 journey only) - controller OOM on a large file.
- Fix: put each workspace on a size-limited filesystem (XFS project quota / loopback ext4 / tmpfs with `size=`), add `--ulimit fsize=<cap>:<cap>`, poll `du` and kill on breach, stream+cap reads in ingress.

### M2. Egress allowlist is an exfiltration channel; gateway is not enforcing SNI/Host and is unwired in production - Medium - PLAUSIBLE
- src/panestria/sandbox/egress.py:117-160 (`_Connect.handle`), allowlist at :163-168 (`api.anthropic.com`, `claude.ai`, `platform.claude.com`).
- The gateway is a raw CONNECT tunnel: it validates the CONNECT authority and pins the IP (good), then relays opaque bytes for up to 16 MiB / 120 s. Anything inside the container that can reach the Unix socket can (a) speak TLS to api.anthropic.com with an attacker-owned API key and upload workspace data to the attacker's Anthropic account, or (b) set a different SNI/Host and use CDN co-tenancy (claude.ai/platform.claude.com are CDN-fronted) to reach non-allowlisted tenants where the CDN does not enforce SNI/Host agreement.
- `grep` shows `EgressGateway`/`native_proxy_relay` are exercised only by tests/integration; no src/ caller. So today this is an unreleased component rather than a live hole, and live workers use `--network none` + seccomp. The risk lands when it is wired.
- Fix: terminate TLS in the gateway (or at least parse ClientHello SNI and require == CONNECT host), require per-session credentials injected by the gateway (so workers cannot bring their own API key), keep the byte cap tiny.

### M3. Native Claude CLI process is host-resident and unsandboxed; safety rests on flags + post-hoc stream parsing - Medium (design residual) - PLAUSIBLE
- src/panestria/brokers/harness/claude_check.py:150-240, claude_proposal.py:94-130, process_runner.py:1-8 (docstring: "lifecycle control, not an OS security boundary").
- Mitigations are strong and I could not bypass them by reading: pinned binary sha256 held by fd, `--safe-mode --restricted --tools "" --setting-sources "" --strict-mcp-config --disable-slash-commands`, `disableAllHooks`, `claudeMdExcludes ["/**"]`, managed-settings presence rejected, canary fixture (hostile .claude/settings.json hooks, .mcp.json, CLAUDE.md in cwd must NOT fire), MCP child launched with `env -i`, Unix socket 0700/0600 with uid check, parser rejects any tool/server/skill/plugin outside the allowlist.
- Residual: the CLI runs as the owner uid with full filesystem access and unrestricted network; the parser detects a violation only after bytes arrive, and a CLI regression/0-day (version is pinned by hash, so only on repin) would run with owner privileges. Peer authentication on the check socket is uid-only (command_transport.py:`peer_identity`), not pid.
- Fix: run the CLI inside the same no-secret container/user-namespace profile with the (to-be-wired) egress gateway; verify peer pid == expected MCP child.

### M4. CI "Secret scan" gate is nearly empty - Medium - CONFIRMED
- tools/secret_scan.py:16-19 has two rules: the PKCS#8 private-key PEM header and `AKIA[0-9A-Z]{16}`.
- PoC (scratchpad/ss/): `BEGIN RSA PRIVATE KEY`, `BEGIN OPENSSH PRIVATE KEY`, `ANTHROPIC_API_KEY=sk-ant-api03-...`, `ghp_...` -> all exit 0 (not detected); only PKCS#8 header is caught. Scans tracked files only, never history. `.gitignore` also lacks `*.pem`, `*.key`, `*.token` although the phone feature stores `activity.token`, TLS cert/key next to config (path rules require absolute paths, so likely outside repo, but nothing prevents it).
- I ran a separate regex sweep over `git grep` and `git log -G`: no real secrets are present (repo is clean today).
- Fix: adopt gitleaks/trufflehog (or add RSA/EC/OPENSSH, `sk-ant-`, `sk-`, `ghp_`/`github_pat_`, JWT, `.env`-style rules), scan history in CI, extend `.gitignore`.

### L1. Unauthenticated `/openapi.json`, `/healthz`, `/readyz` served with no Host check; FastAPI 422 before auth - Low - CONFIRMED
- src/panestria/api/main.py:49-56: `FastAPI(docs_url=None, redoc_url=None)` but `openapi_url` left default. Contrast api/proposal_demo.py:58 which sets `openapi_url=None`.
- PoC (poc_api.py): `GET /openapi.json` with `Host: evil.example` -> 200, 39,718 bytes listing every route; `GET /readyz` with evil Host -> 200/503 body; `GET /v1/approvals?limit=abc` without token -> 422 with pydantic `detail` (route/param schema and echoed input) because validation runs before `authorize()`. DNS rebinding from a browser can therefore read the schema/DB-readiness. All token-bearing routes correctly returned `invalid_host` / `origin_denied` / `unauthorized` (PoC matrix of 12 Host forms: userinfo, `#@`, suffix, `127.1`, `0x7f.1`, trailing space - all denied).
- Fix: `openapi_url=None`, central RequestValidationError handler returning `error_body`, apply the Host allowlist as ASGI middleware for all routes (it is already done in BrowserSecurity for browser modes).

### L2. Case-sensitive path denylist lets `.GIT/`, `.Claude/`, `.MCP.json`, `.ENV*` into candidates - Low (Medium on case-insensitive checkout hosts) - CONFIRMED
- src/panestria/verification/git_snapshot.py:114-132 (`_safe_path`), also sandbox/runner.py:136.
- PoC (poc_paths.py): `.claude/settings.json` rejected but `.Claude/settings.json`, `.CLAUDE/...`, `.MCP.json`, `.ENV`, `.Env.local`, `.GIT/config`, `.SSH/id`, `.claude ` (trailing space), `.git.` accepted; `git mktree` accepts all of them (scratchpad/gt), so Panestria's filter is the only guard. Unflagged persistence/exec vectors also pass: `.github/workflows/*`, `.husky/`, `.githooks/`, `.vscode/tasks.json`, `.cursor/`, `CLAUDE.md`, `AGENTS.md`, `Makefile`, `.gitmodules`, `.gitattributes`.
- Impact: a prompt-injected worker plants agent/IDE/CI config in a candidate that, after owner-approved merge, is executed by Claude Code (macOS/Windows case-insensitive FS), the IDE, or CI. Owner review and independent verification are the compensating control.
- Fix: compare `part.casefold()` (plus NFKC, strip trailing dots/spaces), add the agent-config/CI/hook names above to an explicit review-required (not silent) set.

### L3. `require_current_policy` is fail-open when `policy_version == 0` - Low - CONFIRMED (code)
- src/panestria/kernel/repositories/policy.py:79: `if row[0] != 0 and supplied_ref != ...`. For a project with no configured policy any `supplied_ref` passes approvals request/decide for `contract_consent`. Merge dispatch still fails closed (`current_policy` raises `policy_unconfigured`, build_merge.py `_authorize`). Fix: treat 0 as deny except for the explicit bootstrap path.

### L4. Approval preview validation is loose; safety relies on dispatch-time revalidation - Low/Info - CONFIRMED
- src/panestria/contracts/approval.py:27-45. PoC (poc_digest.py): `expires_at` regex-only (`9999-12-31T23:59:59+00:00` and the impossible `2026-13-45T99:99:99+00:00` accepted), `destination` accepts Cyrillic homoglyphs/newlines/trailing space, `expected_base` and `policy_version` free text. Each of those changes the digest (binding holds); canonicalization is single-implementation, sorted keys, `required_checks` sorted (order-insensitive: True), `extra="forbid"`. Downstream `MergeSpec.validate` (`^refs/heads/[A-Za-z0-9_/-]+$`, 40-hex), `claim.target == destination@candidate`, tree equality, `merge-base --is-ancestor`, `update-ref` CAS with old value, evidence/policy/verifier-bundle re-check make a malformed preview fail closed, but the owner could be shown a homoglyph destination and a never-expiring approval. Fix: strict regex + datetime parse + max TTL in `ActionPreview`.
- TOCTOU/replay conclusion for the bound effect: no bypass found. `decide`/`continue` lock project->task->approval, single-use `approval_consumption`, idempotency key hashed over (id, digest, version, decision), `authorize_dispatch` re-reads approval row `FOR UPDATE` and re-derives the MergeSpec from the immutable evidence bundle.

### L5. Phone pairing availability limits - Low - CONFIRMED (code)
- src/panestria/kernel/phone.py:24-29: more than 256 phone_device rows ever created -> `phone_device_history_limit`, with no prune path (permanent lock-out of new pairings). api/phone.py `PhoneBoundary` global pairing limiter (10/min) is shared by all allowed LAN clients, so one allowed client can starve pairing. Pairing code entropy itself is good: 128-bit (phone) with TTL 120 s; loopback flow is 32-bit with 5 attempts/min/client -> <=10 guesses per code lifetime (~2.3e-9). Not exploitable.
- Positives verified: phone mode rejects bearer entirely, enforces https scheme + exact Host, GET allowlist of 6 paths + pair/logout, rejects Forwarded/X-Forwarded-*, peer IP allowlist, websocket closed, `no-store` + CSP applied by BrowserSecurity/PhoneBoundary, cookie HttpOnly+Secure+SameSite=Strict, 1 h TTL, per-request revocation lookup (including between SSE frames), `phone_device.role` row required, TLS key/cert permission and sha256 pin checks via fds (`/proc/self/fd`), TLS >= 1.2.

### L6. R0 `serve.py` hand-rolled HTTP server and dev defaults - Low - CONFIRMED (code)
- src/panestria/api/serve.py:102-190: no per-connection read timeout or concurrency cap (`readline`, `readexactly` can hang forever; slowloris from any local process); duplicate-Host handling is delegated to Starlette (BrowserSecurity rejecting duplicates is not mounted in this server); status line always `HTTP/1.1 <code> OK`. Makefile:42,49 defaults `PANESTRIA_TOKEN=synthetic-loopback-token` (predictable, >=16 chars passes `GoalApi`), and the token is passed via environment (visible in /proc/<pid>/environ to the same uid). Loopback-only by `_is_literal_loopback`, so Low. Fix: use uvicorn with `server_config()` like every newer mode; require a generated token file.

### L7. Vault pointers/status are unauthenticated metadata; no key rotation - Low - PLAUSIBLE
- src/panestria/memory/vault.py:read(): AAD authenticates the revision identity, but `profile.current_revision`, `status` (ACTIVE/SUPPRESSED) and `row_version` are plain columns. An attacker with DB write (outside the stated threat model, "host administrator compromise") can roll back to an older valid ciphertext or un-suppress a profile. Keys are generated once (`SecretServiceProfileKeys.provision`) and never rotated; Python `SecretBytes` is not zeroized. AES-GCM use itself is correct (random 12-byte nonce, <=1024 revisions per key, `InvalidTag` -> generic integrity error, key checked 32 bytes, Secret Service transport must be encrypted and non-temporary).

### Info
- I1. IDNA2003 (`str.encode("idna")`) in `https_target` folds e.g. `faß.de` to `fass.de`, so the fetched host can differ from what a browser (IDNA2008) shows the owner. Not an SSRF issue (resolution is post-checked); it can mis-attribute provenance. Consider the `idna` package with UTS46 strict.
- I2. `_public_unicast` depends on CPython's `ipaddress` registry (differs by patch version; the code already patches 3fff::/20). It allows globally routable special-purpose space such as 192.0.0.9, 192.88.99.1, 2001:20::/28 (IANA global=true). Acceptable; pin the interpreter and keep the explicit list tests.
- I3. docker/git/ollama are resolved via PATH (`["docker", ...]`) in runner.py:`_docker`, runtime.py; git calls use a scrubbed env with PATH=/usr/bin:/bin. Local-user PATH hijack is out of model.
- I4. Docker daemon is root and the owner is effectively root-equivalent via the docker group; no userns-remap/rootless/gVisor; seccomp is Docker default plus the stacked AF_INET/AF_INET6 denial from no_network.py (x86-64 only; any other arch exits 125 = fail closed). `_validate_effective` does not assert `seccomp`/`apparmor` options, so a daemon-level `seccomp=unconfined` default would not be detected.
- I5. Workspace entry check in runner.py:130-137 uses `rglob` (O(n) walk, TOCTOU only vs the controller itself) and rejects symlinks escaping the workspace, hardlinks (`st_nlink>1`), `.ssh/.aws/.env*`. Post-run capture (`candidate.py`) is excellent: `fwalk(follow_symlinks=False)`, `O_NOFOLLOW`, regular-file + nlink==1 only, stat before/after, size/entry caps, git objects built from bytes with `hash-object --no-filters`/`mktree`, never running worker git/hooks.

## httpx2 / supply-chain verification (item 8)
