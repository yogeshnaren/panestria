# Exact model identity before a local Build draft

The opt-in [Ask manifest](94-PINNED-LOCAL-MODEL-MANIFEST.md) now extends to bounded
JSON Build plan and repair proposals. Existing defaults remain unbound. Private
PlanModelSettings can name a separate owner-selected `model_manifest_file`.
Preparing new work reads that private file and snapshots a strict CPU JSON/no-tool/context-compatible
expectation before preparing any request, disk journal or durable repair intent.

The owner CLI can save public identity from an already running pinned ordinary
Ask service. It starts no inference, creates one fresh0600 output and refuses
overwrites/cache/runtime destinations. `--json-output` derives the JSON formatting
expectation from that observed model identity. This is application metadata, not
a fresh observation, model-quality certificate or training-purpose right.

The proposal request digest includes the selected manifest digest. Request/journal
files retain the original selection before the existing `before_dispatch` hook
acknowledges a durable repair turn. Startup never modifies that request afterward.
The owned CPU runtime verifies cached artifacts/isolation, describes its actual
JSON profile and binds the provider exactly once. Wrong engine/template/tokenizer/
format identity refuses inference instead of replacing the acknowledged pin.

Returned identity must match the original request before a validated proposal is
published. Successful/failure receipts retain the original public manifest; no
proposal is staged/accepted, worker dispatched or merge authorized by this step.
The same path serves finite repair drafts; original source/current-policy checks,
intent-before-dispatch, cumulative turn/wall charges, uncertain-return blocking
and protected outcome hashing remain unchanged. A denied admitted turn stays
charged. A different new-work manifest cannot rewrite old files or reset budgets.
Canonical repair replay uses the original retained outcome and performs no model
turn, even after the selected new-work file changes or becomes unavailable. Pure
configuration loading, repair construction and replay never open that file.

JSON/raw-text profiles are explicitly distinct; implicit format conversion at
dispatch is refused. Other research query/synthesis and GPU paths retain their
current behavior; general replacement/adaptive selection/quality/trial gates are
not completed by this component. Tests distinguish actual PG/files/CLI behavior
with declared generation fixtures from a separately selected existing-cache CPU
JSON/Unix-socket journey. Owner settings/services/cache remain untouched.
