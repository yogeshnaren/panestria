# Offline Build proposals and trusted final-node compilation

AOS-025-S2 now supplies one direct structured local-model proposal path. Existing
canonical plans, exact consent, task membership and handoffs remain the database
boundary. This new operator command reads explicit private contract/inventory
files; it does not read a repository, decrypt a profile, connect to PostgreSQL,
stage/accept a plan, admit workers, grant policy or publish a merge.

The initial model interface asks for **editing assignments only**. Symbolic task
names/dependencies, listed worker/capabilities, literal paths and existing check
keys are untrusted. The controller creates UUIDs, binds the exact contract and
complete inventory hashes, and adds the unique final `trusted-integrator` node.
That node depends on every edit, covers their complete path union and includes
all original goal checks. It does not acquire an execution or merge grant.

Before generation, reserve `min(90, goal_wall_seconds // 2)` for that final node;
only the remaining goal wall envelope is available for all edit attempts. The
inventory must contain the declared trusted-test-runner integrator and allow at
least two nodes/two levels. The model cannot select the integrator as an editor.
The existing full graph/scope/capability/check/aggregate retry-budget validator
then checks the complete compiled plan. A caller cannot make monetary, policy,
privacy, command or check definitions part of the model's authority. The initial
route accepts zero API cash only. Simple single-edit plans need no graph runtime;
the trusted final node is an explicit verification step.

The initial live draft showed why this split matters: the small pinned model
omitted the final dependencies, and validation rejected it. That original result
remains a failure. The revised edit-only interface makes the mandatory final
verification structure deterministic; it does not silently repair an invalid
old response or mark model output as verified code.

Generation uses the existing pinned local provider/model/cache and its nonroot,
network-disabled CPU runtime. Admission preserves foreground headroom and an
existing owner controller. The call has a60second generation deadline,1024output
tokens and4096context bound; the existing runtime separately bounds startup and
cleanup. Oversized input is refused, not truncated. There is no fallback, model
download, external provider, automatic retry or free-form shell/tool access.

A fresh private run directory records frozen contract/inventory/request, STARTED
journal, bounded complete raw response, compiled proposal, validation and final
receipt. UUID/hash/model/digest/latency/token metadata explain the observation.
Completed malformed responses remain private with UNAVAILABLE; incomplete calls
may lack a raw response. A crash may leave STARTED, which means unconfirmed.
Reusing any run directory is refused, including after failure; an explicit new
owner invocation is required. These files are proposal provenance, not another
canonical task or acceptance store. They must not be committed as private data.

The owner reviews the proposal, then separately stages the frozen copies and
accepts the exact canonical digest through existing commands. Structural
validation does not assess decomposition quality or semantic completeness. The
current native executor supports a narrower two-independent-Claude fork/join;
a general local proposal may require a supported execution shape before running.
Bounded canonical revisions, failure reconciliation and repair accounting remain
AOS-025-S3/X10 work. No LangGraph dependency is added without a concrete need.
