# Canonical background intent and eligibility

Narrow AOS-012-S5 to a reviewed durable queue and truthful readiness observation
before adding any external dispatcher. Original plans/policies must already be
accepted, PUBLIC, within original bounds and supported declared native roles.
The owner explicitly reviews the exact background policy digest; it cannot grant
new data/tool/provider scope or cash. Draft/prepare are read-only to canonical state.

Queue bindings and withdrawals are immutable facts in the existing same-Postgres
task_event ledger. They reference the existing goal/final task, exact accepted
plan/contract/inventory, declared-input context, bounded policy and opaque account
scope. There is no second task-status authority or new migration. Existing
attempts/leases/invocation receipts/handoffs/approvals remain authoritative.
Fleet then project locks serialize enqueue/replay, last-write global event append
preserves transaction ordering, and unique-by-application item/plan bindings are
rechecked under that same fleet lock. Rollback leaves no queued fact. Corrupt
hash/scope fails closed. History/intake/read/file-size bounds are explicit.

Eligibility is a read-only projection, not an ActionPermit. It rechecks current
accepted plan/membership/policy, original budgets, task state, held fleet capacity
and active Ask. Each quota window/source remains distinct; reserves use matching
units, without turning a percentage into tokens or cash. Unknown and estimated
best effort require separate explicit policy. Latest numeric owner/provider zeros
remain visible across later null reports until superseded or a known reset;
reset does not restore an invented balance. Owner priority and reported-reset
arithmetic are retained inputs, not an optimizer or inferred economic value.

Billing reports are separate scoped owner observations, with bounded freshness.
They do not certify the provider's actual settings or authenticated account.
The view states source/confidence and NOT_ASSESSED runtime/no-spill qualification;
no model identity or current account proof is invented. Actual dispatch must add
current authenticated profile/account binding, no-extra-spend evidence, one-job
admission/reservation, foreground yield and unknown-call reconciliation. It must
never use this view alone to grant a provider call. A zero API cap or estimated
CLI cost does not prove that a subscription cannot consume usage credits.

Withdraw only the exact queued binding without cancelling/falsely freeing its
underlying work; current cancellation/physical-return protocols remain required.
Queue history survives policy revocation and restart, while expired/changed policy
cannot authorize work. Source-bound component evidence uses real PG/CLI plus
explicit synthetic quota/billing/host values; no live pass or dispatcher is claimed.
