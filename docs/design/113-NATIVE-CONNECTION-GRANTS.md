# Selected native account/context grants

This AOS-008-S4/S5 component intersects an explicitly selected reviewed connection
with the existing PUBLIC Claude Build controller. It reuses the declaration
ledger, supported pinned pseudonymous account probe, protected observation CAS,
worker authority hooks, current policy/certificates/leases and one-use invocation
records. It creates no credentials, account registry, task-state store, generic
file connector or background permission.

Version1 manifests and unselected legacy Build settings retain their serialization
and policy-only behavior. Version2 is a closed native capability: the logical
`claude-subscription` route, one pinned private profile reference, exact original
account/configuration/runtime/requested-model identity, PUBLIC read/write/send,
no spend/delete or arbitrary origins. A logical route does not pretend to be an
observed physical host allowlist. Declaration views stay UNVERIFIED/unavailable;
actual adapter/secret/OS/network and cumulative qualification remain separate.

The terminal shows the route and budget units before exact owner approval. A
native-template command probes only existing supported account metadata and
writes a private proposal for separate review. The owner explicitly selects the
approved grant ID/version and original observation in private Build settings.
Original account consent does not expire merely because the metadata sample
ages: a fresh matching probe before work/disclosure and after return is mandatory.
No report renews quota/billing consent or changes extra usage settings.

Each native worker reserves one call and exact selected PUBLIC context bytes in
an immutable task_event before its invocation can be prepared. Calls mean native
process invocations; bytes exclude fixed prompts, CLI output, authentication and
wire traffic. Those retain their existing independent process/transport bounds.
This distinction is part of the typed version2 contract. At most64 calls per
grant version bounds ledger reads; no uncertain reservation is refunded. Exact
attempt reinspection is idempotent, never permission to redispatch. Wall time
starts at the first reservation and includes idle time; renewal needs new review.

Reservation takes the project lock before task locks, serializing capacity and
revocation across goals and controllers. Subsequent guards use read-only queries
so two worker monitors never upgrade project share locks. Selected account,
profile, binary/runtime, current version/policy/certificate, original expiry and
budget intersect worker launch, scoped tools, watchdogs, evidence/handoff and
final trusted verification/publication. Existing background guards compose with
this guard rather than being replaced. Protected owner merge remains a separate
local policy/exact-approval authority; this connection cannot grant it.

Failure analysis and required checks:

- Revoke/replace/expire or change policy/account/profile/runtime: deny future
  effects, cancel the existing supervised native process, retain physical
  receipts/unknown claims and publish no new acceptance. Already sent content
  cannot be recalled; provider/backup retention remains outside this component.
- Concurrent shared capacity: serialize reservations; reject excess calls/bytes
  without model dispatch. Lost acknowledgments consume capacity conservatively.
- Bad/missing/tampered original observations or reservation bodies: fail closed;
  no raw identity, auth material or private profile path enters worker context.
- Exact PUBLIC account/native fixture journey must reach independent final
  review; revoked-before-start, in-flight revocation, mismatched account, concurrent
  budget, final publication and background composition must be exercised with
  actual disposable PG/Git/MCP/Docker and explicit provider/account fixtures.
- Old connection/Build contracts, read-only monitoring, typed OpenAPI and all
  exact-head CI checks must remain compatible. No source certificate is relabeled.

No owner live profile/network/service/database is configured by implementation
tests. This is a selected application-authority component, not completed generic
enrollment/secret injection or TC05-TC08/G3/owner trial qualification.
