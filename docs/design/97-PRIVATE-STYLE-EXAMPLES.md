# Bounded private style examples in the encrypted profile

This completes a specific missing AOS-017-S4/MVP-X08 component: owner-supplied
presentation references travel with the approved encrypted communication field
into the existing explicitly selected offline profile Ask overlay. It does not
establish verified factual examples, style quality, training permission,
cross-harness portability or a release pass.

Reuse the profile vault, exact correction/version/expiry/suppression checks and
approved communication field; add no store, field, migration or grant. A style
may contain at most two examples, each with a unique profile-local reference,
256-byte input and 384-byte response. Require visible printable text/newlines;
reject control/bidi/format characters. Example references become meaningful only
with the parent immutable profile revision/ciphertext source already bound by the
request. No content-derived ID or public private-text fingerprint is introduced.

Default model serialization masks example text. The explicit private serializer
is used only to build the encrypted communication snapshot and authorized
in-memory local overlay. The compiler keeps preferences separate from untrusted
examples, labels them RESTRICTED/owner supplied/policy authority NONE and grants
no training permission. Preserve legacy serialization and compiled prompt bytes
when the examples tuple is empty. Existing context limits reject oversized
selections without truncation or fallback; the runtime still enforces offline,
current policy/source and output-retention boundaries.

The existing owner keyboard editor optionally reads one absolute private file
once, using the bounded/no-follow/owner-only configuration reader. It neither
writes nor deletes that input file. Import is an explicit complete replacement;
no file means preserve current examples. Empty import removes examples only
through the separately confirmed encrypted revision. The terminal shows counts,
then a literal wrapped/scrollable local view. Saving a nonempty set requires
reaching its end and acknowledging review before the separate exact save screen.
Local-context approval remains independent. One write attempt only; uncertainty
requires canonical inspection. Wider fields, approvals and expiry are preserved.

No example enters ordinary context packs/FTS/learning, a general prompt hash,
traces, a public export or native/cloud harness. This path does not evaluate the
model's response, qualify OS keys/model boundaries or refresh old source-bound
certificates. Component checks use synthetic statements/keys/model and real
PG/encryption/HTTP/PTY. Actual owner-profile onboarding and quality remain scoped
validation work.
