# Canonical Build progress projection

Deliver the first AOS-025-S4/X10 inspection path by projecting existing immutable
contracts, plans/consent/membership, handoffs, evidence/check runs, attempts,
invocations/releases and exact merge receipts. Retain an explicit create-once
private export plus SHA256, rather than introducing another authoritative task
ledger or changing existing evidence bytes. Every snapshot binds one repeatable-
read PostgreSQL observation/event cursor and current owner/project authority.

The original contract's acceptance keys map to final-tree evidence; original
non-goals remain visible and NOT_ASSESSED. Node milestones expose protected
candidate/check/handoff refs separately. Source-bound PASS/FAIL inspection reuses
the existing verifier checks through BuildEvidenceService.observed; current still
requires success and retains its dispatch/merge refusal. Missing/corrupt/stale
proof cannot contribute to the bar. Database task status, observed verification,
owner merge and release acceptance are distinct facts.

Finite versions/full original wall envelopes come from existing canonical plans.
Unknown/expired held work has priority over inferred readiness. A CLAIMED live
call remains activity; a heartbeat is only a later event cursor. Repeated failure
fingerprints bind unchanged tree, original contract, verifier bundle and failing
required check specs/verdicts, excluding task IDs and commit timestamps. The view
reports attention/next action and never grants recovery, retry, completion or
merge authority. Current policy denial fails inspection rather than renewing a
grant. Historical low-level claim inspection remains separately available.

This is partial S4 delivery: explicit semantic requirement/milestone annotation,
rubric/non-goal assessment, controller enforcement of repeated-failure policy,
qualified restart/handoff and unified Mission Control remain pending. No new
schema migration, process watcher, provider call or automatic storage cleanup.
