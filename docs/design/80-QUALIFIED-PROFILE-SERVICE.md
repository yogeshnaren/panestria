# Explicit qualified personal service

AOS-011-S5/S6 and AOS-017-S4 gain a supported, separately selected launch path.
The default local/activity launchers still mount no profile vault. This task
changes neither the original slice envelopes nor their release scenarios.

The private wrapper references existing offline Ask settings, an exact protected
profile qualification and a finite list of existing scoped OS handles. Scope is
checked against the existing owner/project, with IPv4 loopback for current
profile clients. It cannot specify a provider, key bytes, database URL, project
grant or arbitrary runtime. The CLI requires explicit restricted-offline intent.
Existing keys must be readable before starting the owned listener/model; there
is no OS key creation, collection unlock, fallback, migration or installed
service. The existing port reservation, PrimaryLease, resource admission,
no-orphan-reaping behavior and owned lifecycle are reused.

A distinct `ISOLATED_OS_KEYS_CPU_PROFILE_ASK_ONLY` observation runs two fixed,
reviewed actual tests from a clean checkout in its frozen environment. It uses
an isolated synthetic OS keyring and existing pinned CPU engine, supported API
factory/lifecycle and physical loopback HTTP, preserving old historical ASGI
observations. Skip/error/failure/dirty source/other modes cannot establish a pass.
No caller-supplied XML or generic PUBLIC Bash certificate is accepted. The run
has a240s deadline/1MiB log limit and graceful fixture cleanup before escalation;
its run result/raw logs persist privately. Interrupted cleanup remains unknown.
The first runtime fingerprint happens before that test deadline; the outer
operator process and OS I/O are not claimed to have a hard interruption bound.

A protected CAS proof retains its original candidate/raw JUnit bytes and expires
within24h. It binds production/probe source, uv.lock and actual installed package
versions, kernel/boot/UID and Python/D-Bus/keyring/Docker-client/Ollama binary and
library bytes. Stat-keyed public digest caching avoids rehashing all library
bytes on every key load. Pinned image/model identifiers supplement existing full
blob digest/effective container checks at startup. Documentation changes may
preserve inputs without relabeling the observed source. This trusts the local
operator, filesystem/kernel and dependencies; it is not an attestation against a
host administrator, daemon compromise or changes to already loaded native code.

The allowlist key broker checks the exact proof and current inputs before and
after each existing Secret Service load. Ordinary vault versions/scope/AAD and
context purpose/approval/current policy continue to apply. After model return,
the HTTP path reconstructs and checks the selected profile inside the publication
transaction. A late expiry/locked key/correction/suppression/policy change withholds
the answer and keeps the canonical unavailable receipt. Suppression uses no key,
so withdrawal remains available after expiry. No automatic qualification renewal,
model redispatch or newest-profile selection is introduced.

Four focused component journeys exercise the real PG/crypto/HTTP/CLI path with
explicit model/key/qualification fixtures; actual runtime evidence remains a
separate execution mode. All CI and original obligations stay required. The narrow
operator proof does not complete TC06–TC08, owner-keyring compatibility, example
retention/purge, measured resource/quality budgets, personal-platform acceptance
or R3/G3. Those requirements remain visible in progress and original manifests.
